# AGENTS — SyncBot

This file is the primary instruction set for AI coding agents (Cursor, GitHub Copilot, Codex, Claude via `CLAUDE.md`).

## Project snapshot

SyncBot is a **Slack app** that syncs messages, threads, edits, deletes, reactions, and media across **multiple Slack workspaces** (and optional **federation** between instances). The runtime is **Python 3.12+**, **Poetry** for dependencies, **SQLAlchemy** + **Alembic** for the database, and **Slack Bolt**.

Deployments supported in-repo: **AWS** (Lambda + SAM) and **GCP** (Cloud Run + Terraform). Application code under `syncbot/` must stay **cloud‑neutral**; provider-specific pieces live only under `infra/aws/`, `infra/gcp/`, and deploy workflows.

## Repo map (short)

- `syncbot/` — application (`app.py`, handlers, db, federation).
- `syncbot/db/alembic/` — schema migrations.
- `tests/`, `infra/aws/tests/`, `infra/gcp/tests/` — pytest suites.
- `infra/aws/`, `infra/gcp/` — SAM/Terraform, bootstrap, CI deploy helpers.

See [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) for Dev Container / Docker Compose / native setup.

## Hard rules (guardrails)

1. **Provider-neutral `syncbot/`** — do not add `boto3`, `google.cloud`, or other cloud SDK imports under `syncbot/`. Use `infra/<provider>/` and workflows for provider code. This is also enforced in CI (`forbidden-imports` job).
2. **Version & changelog** — do not bump `pyproject.toml`’s `version` or `syncbot/constants.py` `__version__`, or add a `## [X.Y.Z]` heading in a feature PR. Releases on `main` are automated with **python-semantic-release**. Put Keep a Changelog notes (**Added** / **Changed** / **Fixed**, **[1.2.0](CHANGELOG.md)** length) under `## [Unreleased]` below `<!-- version list -->`; the release job retitles that heading to the version and date and copies that section onto the GitHub Release. If Unreleased is missing, PSR drafts from `feat` / `fix` / `perf` subjects. Polishing an already-released heading is OK. See [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md) and [CONTRIBUTING.md](CONTRIBUTING.md).
3. **Requirements files** — do not edit `syncbot/requirements.txt` by hand. Change dependencies in `pyproject.toml` and run the pre-commit `sync-requirements` hook or `poetry export` as in [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md).
4. **Secrets** — never commit real `.env`, `.env.deploy.*` (only `*.example` templates), private keys, or large artifacts. Do not commit `.aws-sam/build` output.
5. **Deployment branches** — on a **fork**, do not push to `test` or `prod` as a casual step; those branches deploy. Canonical releases run only on **F3Nation-Community/slack-syncbot** `main` (see [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)). Forks pull `main` and promote to `test`/`prod` themselves.
6. **Conventional Commits** — PR titles and commit subjects are one short imperative line (`fix: …`, about 72 characters). Skip the body unless you need `BREAKING CHANGE:` or a single clause that will not fit. See [CONTRIBUTING.md](CONTRIBUTING.md).
7. **Docs** — if behavior, env vars, or deploy steps change, update the relevant `docs/*.md` (and [docs/INFRA_CONTRACT.md](docs/INFRA_CONTRACT.md) if the runtime contract changes). Follow **Docs voice** below. The **Message Sync Flow** walkthrough in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) links to functions by `#L` line; when you move, rename, or split those functions, retarget every link. Keep the mermaid same-instance / cross-instance, and infra-agnostic (Slack → SyncBot → Slack).
8. **Plan files** — write working plans only under **`.plans/`** at the repo root (gitignored). Never put them under `docs/` even if ignored — that looks like operator docs. Never commit plan files. `docs/PLAN_*.md` and `PLAN_*.md` stay gitignored as a safety net for leftovers.

## Docs voice

Operator-facing docs (README, `docs/*.md`, `.env*.example`, `infra/gcp/example.tfvars`) should read like a helpful teammate: friendly and explanatory, not clipped or telegraphic. Write full sentences (do not drop “the” or “a” to shorten a line). Prefer a short paragraph over a dense jargon pile.

Stage is only **`test`** or **`prod`**. Do not use `YOURSTAGE` as if the name were arbitrary. Show the real values (`--env test`, `slack-manifest_test.json`, `syncbot_test`) and mention `prod` as the other choice. Keep `YOUR_*` for values that really vary (region, host, username).

**Changelog / GitHub Release notes** follow Keep a Changelog and **[1.2.0](CHANGELOG.md)** length: one short line per bullet, not the operator-docs paragraph style. See `.cursor/rules/50-changelog.mdc`.

**Example names** — Use generic fixtures, not operator screenshots or community-specific names. Workspaces: `Workspace A`, `Workspace B`. Channels: `#general`, `#announcements`. People: `Ada Lovelace`. Connection labels: `Partner Org` (not a workspace name). A missing workspace name is `Workspace`. URLs: `https://ws-a.example`, `https://peer.example`. Do not copy names from screenshots.

## Common pitfalls

- **Slack Free.** Target audience is Free workspaces. When reading Slack API docs, keep only Free or all-plan facts. Ignore Slack Connect, Enterprise Grid, remote-files, paid retention, and Audit Logs. `hidden_by_limit` and `storage_limit_reached` are Free. Slack's per-file limit is 1 GB; do not invent a smaller app cap. Do not add `files.info` for `check_file_info`.
- **Bot identity is per workspace.** Never cache `auth.test` under a process-wide key. A warm process handles many workspaces; reusing workspace A's bot member ID on B makes `conversations.invite` fail with `user_not_found` and can skip the unconfigured-channel leave handler. Prefer Bolt's request-scoped `context["bot_user_id"]`, and cache `auth.test` keyed by bot token.
- **Settings are modal-only.** Instance fields (`federation_enabled`, `soft_delete_retention_days`, `workspace_block_list`) use `instance_settings` on the primary workspace. Workspace fields (`allow_private_channels(team_id)`, extra managers) use `workspace_settings`. Leftover env (`ALLOW_PRIVATE_CHANNELS`, `SOFT_DELETE_RETENTION_DAYS`, `SYNCBOT_FEDERATION_ENABLED`, `REQUIRE_ADMIN`) is ignored and warned. `PRIMARY_WORKSPACE` and `ENABLE_DB_RESET` stay env. The Workspace Block List is Team IDs (`T` + alphanumeric). Ack rejects the primary Workspace and a group Owner. Newly added installed IDs call `apps.uninstall` then `uninstall_workspace`. OAuth `save` / `save_bot` refuse a blocked team (do not persist). `heal_workspace_to_local` is refused while listed. Removing an ID does not auto-reinstall.
- **Federation on/off** is `helpers.federation_enabled()` at call time (Settings DB), not an import-time constant. Do not freeze at HTTP listen. Default off on a new install.
- **Private membership.** Write `Sync`/`SyncChannel` then invite. Public = bot `conversations.join`; private = `conversations.invite` with the acting user's `xoxp` only, gated by `allow_private_channels(team_id)`. Failed invite rolls back and DMs. Leave-on-unconfigured stays. Treat `already_in_channel` / `cant_invite_self` / `method_post_only` as success. Invite only `U…` member IDs, never `B…`. Resume passes Bolt `context` only when the channel's workspace is this request's workspace. Use `lookup_channel_meta` for Channel names (the bot cannot see a private Channel it has not joined).
- **Native `conversations_select`.** Do not rebuild channel pickers from `conversations.list` (~100 cap). The filter is advisory; validate on submit.
- **Helpers import submodules only.** Never `import helpers` inside `helpers/*.py` — `helpers/__init__.py` circular-imports at process start. See [`syncbot/helpers/sync_cleanup.py`](syncbot/helpers/sync_cleanup.py).
- **`is_workspace_admin` vs `is_workspace_manager`.** Admins open Settings, Backup, Reset, and External Connections (primary only). Managers configure groups and syncs. Authorize and Refresh stay for everyone.
- **Direct reactions** use `get_user_token(target_team_id, mapped_user_id)`, never the event team. Never send `xoxp` on federation envelopes. Do not store reverse-map results as target `xoxp` lookup keys.
- **User-token echo.** Native `reaction_added` is the mapped person, not the bot. After user-token add/remove, `remember_user_action`; `take_user_action_echo` **inside** `run_claimed` (not `processed_events`; consume-once). Fingerprint target channel + six-decimal Slack `item.ts` + emoji (`slack_message_ts`). File shares posted as the mapped person have no `bot_id`: remember Slack file ids from `files.getUploadURLExternal` **before** `files.completeUploadExternal` shares into the Channel; inbound events **peek** `kind=file` and `kind=message` (`has_user_action_echo`, do not consume) so `file_share` and a later `message_changed` skip. Remember the share message ts, never the thread parent. Copy PostMeta is written when the target post lands. Inbound *creates* of that copy are skipped by echo and `post_meta_exists_for_channel_ts`. Follow-ups on a publishing Channel (reaction, thread, edit, delete) still originate from the shared `post_id`; echo skips the apply SyncBot just wrote.
- **`post_meta.ts` is DECIMAL(16, 6).** Never `float(ts)` to persist or compare. A current Slack ts does not fit in a float, so reactions and thread replies miss older rows. Use `post_meta_ts(ts)` for that column (write and `==`). `slack_message_ts` is the string form for Slack API kwargs and echo fingerprints (`str(Decimal)` drops trailing zeros). Do not add another converter.
- **Hybrid thread.** Target `invalid_name` never threads. Probe target emoji names with the bot token **only** when about to post a Hybrid thread in **another workspace** (no target `xoxp`, or that token hit `_NO_AUTHORIZE_ERRORS`). Same-workspace Hybrid skips the probe (shared emoji catalog). Federation inbound is a different Slack workspace — probe it the same as same-instance cross-workspace. Origin having the emoji does not mean the target has it. Direct-only and a successful native add never probe. Off is a no-op for add and remove. Inbound reaction apply is last-write-wins on envelope `event_ts`. Do not use `emoji.list`; the target bot `reactions_add`/`reactions_remove` probe is the current method. Hybrid notices `chat.postMessage` with the Slack thread **root** (`conversations.replies` `thread_ts` when it differs from the reacted ts; channel history does not return replies). Unreact `chat.delete`s target Hybrid notices (children first); never reuse the parent message `post_id`. Off does not delete leftover notices. A target user deleting a notice is a local tombstone only — no origin `reactions_remove`, no other target rows. Same-channel `apply_reaction_to_target` is always skip. Pre-1.4.1 uuid notices: leftover thread scan deletes only bot posts whose text is `reacted with :emoji:`; never a human reply that merely mentions the emoji.
- **Token encryption at rest.** Bot tokens live in Bolt `slack_bots` (`helpers.workspace.get_bot_token`); user tokens in `slack_installations` (via `EncryptedSQLAlchemyInstallationStore`). Never compare two Fernet ciphertexts for equality — decrypt stored token and compare plaintext when refreshing. Federation file-part payloads use the same `DATA_ENCRYPTION_KEY` (`encrypt_bytes` / `decrypt_bytes`). `federation_file_parts` is an in-flight mailbox (TTL ~5 minutes); omit it from backup and migration export. `offer_have` uses stored `part_total` (the sender's part count), not `func.length(payload)` (ciphertext is not plaintext size) and not `max(part_index)+1` (part 0 of N is not a complete file).
- **Home hash is per user** (`home_tab_hash:{team_id}:{user_id}`). Prefix delete on restore still works. Hash payload must include manager/admin role, extra-manager lists, group names, member roles, sync titles, and External Connection fingerprint (peers, allowlists, remote stubs, waiting codes). `app_home_opened` re-publishes the cached blocks when that hash matches. Refresh does nothing when it matches. Post-deploy `views.publish` uses remembered Home viewers in `workspace_settings` (plus extra managers); do not crawl `users.list`. Keep-warm must not republish Home.
- **Home push is the acting user plus hash invalidation.** Do not call `get_admin_ids` / `users.list` to fan out Home. Others refresh on `app_home_opened`. Inbound federation is invalidate-only (no `views.publish`). `/teams` pauses this peer's stubs that left the allowlist. Home **Refresh** publishes this user's tab, then pulses federation allowlists, when the hash changed. An unchanged hash does nothing.
- **User Mapping is a modal.** The ack opens Loading and the work phase fills it from DB mappings only. Never seed, map, or crawl before that fill. **Auto Map Now** updates the open modal via `view_id` (close-only wait view, then the list and last-run line). Never `views.publish` Home for mapping. Auto Map Now from `user_directory.email` with `allow_slack_email_lookup=False` on the button (no source `users.info` either); do not crawl `users.list` on open, Refresh List, Auto Map Now, or group join. **On-the-fly author map** (`ensure_mapped_target_user_id`) is one person, email only (directory then one target `lookupByEmail`); not a full Auto Map Now.
- **Button modals open in the ack.** `action_ack` opens a close-only Loading view for `MODAL_OPEN_ACTIONS` (`views.push` only for Edit Mapping). The work phase fills it with `views.update` by `external_id`. Do not `views.open` or `views.push` again in the handler. No database and no `users.info` on that open. A handler that does not update shows the close-only denial. A failed open and `not_found` do not DM. `view_submission` `response_action` stays in `view_ack`.
- **Route through `routing.py`.** Do not add Bolt `@app.action` / `@app.event` — `app.py` already matches `.*` into `MAIN_MAPPER` / `VIEW_ACK_MAPPER`. A second decorator double-fires.
- **Clean Slack ID renames.** Rename the `action_id` / `callback_id`, the constant in `slack/actions.py`, the handler, and the `routing.py` entry together. Do not keep leftover Slack IDs mapped to the new handler. A stale Home tab may `no_handler` until Refresh; that is expected. Prefixed Home buttons (`join_sync_{id}`) must not share a prefix with a modal picker: `select_join_sync`, not `join_sync_select`. `create_sync` is not prefixed, so `create_sync_select` is fine. Two current buttons may share a handler (`decline_group_invite` / `cancel_group_invite`). Leftover env still warn-and-coalesce; old backup keys still import.
- **Modal field errors only in the ack phase.** `VIEW_ACK_MAPPER` may return `{"response_action": "errors", ...}` (3s budget, no Slack/DB of consequence). After ack, work-phase failures DM the user.
- **`DbManager.get_record` uses each model's `get_id()` column, not always the integer PK.** Pass that value positional or as `id=` only (`team_id=` TypeErrors). `Workspace` → Slack `team_id`. `SyncChannel` → integer primary key. `PostMeta` → `post_id`. Objects are expunged; each call is its own session.
- **Soft-delete + no `ON DELETE CASCADE`.** Active queries need `deleted_at.is_(None)`. Hard deletes go through `purge_sync` / `purge_workspace` (children first, including soft-deleted rows).
- **Imports are `import helpers`, not `from syncbot.helpers`.** Pytest `pythonpath` is `syncbot/` (and `infra/aws/lambda`). Do not add `tests` to it; import fixtures as `from tests.event_fixtures import …`.
- **Link buttons still need a no-op in `ACTION_MAPPER`.** Slack fires `block_actions` for URL buttons (`handle_authorize_syncbot` is the example); without a handler you get `no_handler` in the logs.
- **Never log tokens.** `redact_sensitive` (and request-body `_redact_sensitive`) must include `user_token` and `bot_token`. Do not print `xoxp` / `xoxb`, pairing codes, connection codes, or private keys.
- **Structured events use `log`.** Prefer `log_debug` / `log_info` / `log_warning` / `log_error` / `log_critical` (`from logger import log_debug`). Those wrap `log(event, level, **fields)` — *level* is required, there is no DEBUG default. Stable snake_case *event* is the log `message`. Decision points, not per-loop chatter. Do not add a second event helper. Filter `heal_stub`, `federation_pair`, `migration_export`, `migration_import`, `teams_heal`, `push_teams`, and `live_conflict` for an export/import/heal test.
- **Leave Sync** removes this workspace's `SyncChannel`. Pause/resume only toggles that workspace's channel and ask for confirmation (not red). Pause, Resume, Leave, uninstall, and Edit Sync invalidate every Channel in that sync (`publish_targets:` and membership). `apply_target` re-reads the SyncChannel row so a stale cache cannot write to a paused or left Channel. The last publisher to Leave Sync ends the sync for everyone (`purge_sync`) after a warning. There are no sync owners; any group workspace can Create Sync later.
- **Participation owns reaction direction.** Create Sync offers `publish_only` / `publish_and_subscribe`. Join Sync and Edit Sync offer those plus `subscribe_only`. Reaction UI chooses Hybrid, Direct, or Off. Off does not apply incoming add or remove. Do not revive leftover reaction-direction action IDs or radio fields.
- **Events API dedup is Slack envelope `event_id` + `team_id`** (`run_claimed`), not `event.ts` or `X-Slack-Retry-Num`. Sync fan-out uses one source-canonical envelope (`kind` + `action`) through `run_sync_pipeline`. Missing `event_id` always runs. Failed work releases the claim. Work that is not ready yet (`return False`, for example a reaction before origin PostMeta exists) also releases the claim so Slack can retry. Own-bot, pending-`file_share`, and unsynced subtypes complete the claim as no-ops so retries do not re-run them.
- **Publish/subscribe pipeline.** An origin must publish and a target must subscribe. Discover fan-out with `iter_publish_targets`; `get_sync_list` is gone and must not be reintroduced. Dedupe targets by workspace and channel. Same-instance (live on this install) uses `apply_target`; cross-instance (peer Channel) uses `deliver_remote`. Stub is the database row (`is_stub_workspace`), not a product name. A copy's inbound create never originates a second hop (echo + `copy_exists`). Reactions, thread replies, edits, and deletes on a publishing Channel still fan out on that message's `post_id` even when the row is a copy. Thread *creates* (and files in a thread) fan out locally only to Channels that already have the parent PostMeta. Trusted cross-instance Channels still get that envelope; inbound 409s if the peer has no parent. Edits, deletes, and reactions fan out to every publish target; local apply no-ops and inbound 409s when PostMeta is missing. Federation origin puts the target Channel's Slack ts on the envelope as `target_ts` when origin has that copy row. Inbound replies apply with that field, or with PostMeta on the resolved SyncChannel; edits, deletes, and reactions need that PostMeta row (`target_ts` alone is not enough). Outbound 409 `incomplete_file` restages parts once, then DMs; `assemble_failed` DMs without another upload; `parent_missing` does not DM. Do not key the peer on origin integer PKs. Do not put `thread_post_id` on reaction or edit envelopes. After you change `run_sync_pipeline`, `iter_publish_targets`, `apply_target`, `deliver_remote`, inbound federation apply, `run_claimed`, or the message/reaction handlers, retarget the **Message Sync Flow** `#L` links in [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) (and the mermaid if the hop changed).
- **Limits.** Use a documented Slack fact or a cap infra injects. Slack files are 1 GB. `conversations.history` and `conversations.replies` are Tier 3 (50+ per minute); pace a share-ts lookup at that rate and keep going until Slack returns the ts. Do not add an app-side wait deadline, and do not copy a Lambda or Cloud Run timeout into `syncbot/`. The platform request timeout is what ends a lookup still in progress. `FEDERATION_HTTP_MAX_MB` stays the injected hop cap.
- **Helper names.** Verb-led (`build_`, `get_`, `_format_`, `_parse_`, `_handle_`). Reuse source/target, origin, PostMeta, post_records, envelope, people, channel_ref. Do not invent graph, dest, member_ref, wire, or other synonyms for those.
- **Pytest warnings.** Treat them as part of the change. Do not skip tests or `filterwarnings` to hide SAWarning, DeprecationWarning, or sqlite3 datetime-adapter warnings. `001_baseline` uses current ORM `create_all`; later migrations must skip a foreign key when the column already has one (named or unnamed). A second named copy on SQLite duplicates `FOREIGN KEY` in `sqlite_master` and SQLAlchemy warns. Editing an already-applied revision does not remigrate production. Do not delete `012_federation_webhook_endpoint`: it no-ops when `federated_workspaces` is gone and is still the chain link before 015. Fresh `001` already has the 015–020 shape; those revisions skip existing tables and columns. sqlite3 datetime binds use the adapters in `db/__init__.py`.
- **Slack action icons.** Lead Home/modal action buttons and in-channel/DM action notices with one Slack shortcode from `.cursor/rules/85-slack-icons.mdc`. Pause `:double_vertical_bar:`, resume `:arrow_forward:`, leave `:wave:`, live sync/Refresh `:arrows_counterclockwise:`. Do not icon form labels, context metadata, or Authorize.
- **Message loop / double-post.** Skip only SyncBot's own `bot_id`, not other bots. Ignore Slack `upload` (share-at-upload-time vs later, not new vs parent copy). `subtype=file_share` is a share. A plain **top-level** `message` with a downloadable hosted file is processed; wait for `file_share` only when those files have no private URL yet, or when Slack-hosted video/image blocks are present without one. A later same-ts `file_share` is `copy_exists`. Thread text replies (`thread_ts` ≠ `ts`, no `file_share`, has text) list the parent file and those files are stripped. Also-send-to-channel (`thread_broadcast` / `reply_broadcast`) keeps its files. A new file in a thread is `file_share`, or a file-only thread message (blank text, files present) when Slack omits the subtype. If the file cannot be copied, log `file_share_failed` and DM the source author with `format_error_dm`. `thread_ts == ts` is the parent, not a reply. File-id echo skips kept-file events for the share we just wrote, not a later text reply that lists the parent file. Message-ts echo and copy PostMeta skip the inbound *create* of the copy. If complete-upload omits the share ts, keep reading channel history at Tier 3 until Slack returns it. The platform request timeout ends that lookup. If the upload returns without a ts, remember the in-flight apply (envelope post_id, sync_channel_id, source fields) keyed by Slack file id, and let the inbound own-bot or file-echo `file_share` commit that copy PostMeta. Do not DM a file-share failure when the file is already in Slack. Follow-ups (reply, edit, delete, reaction) look up the parent by ts; if that PostMeta is not stored yet, return `False` so the claim is released. Other bots' `bot_message` events are synced. User-token file shares look like the mapped person; echo and PostMeta must use the share ts, not the parent.
- **File shares** are one native upload for both tokens. The file is the message. Plain text is `initial_comment` (or none when there is no text). Block Kit and a public GIF go on that upload as `blocks`. `initial_comment` together with `blocks` drops the blocks. Bot posts set `username` and `icon_url` (`chat:write.customize`) on every file share, including file-only. User-token posts do not set those. The upload keeps reading the share ts at Tier 3 until Slack returns it. A source thread reply that was also sent to the channel then `chat.update`s `reply_broadcast`. Same-instance and cross-instance both do that in `apply_target`. Complete-upload does not accept that flag.
- **Block Kit is the message body.** Slack `event.text` is a notification fallback: it often strips newlines and truncates (the client "Show more" is chrome on `blocks`, not a second payload). Copy content blocks (`section`, `header`, `rich_text`, …), drop `actions`/`input`, rewrite mentions in place. Do not copy Slack-hosted `video`/`image` Block Kit URLs (`files.slack.com`); the file still goes through download / `file_refs`. A public image attachment (GIF picker) stays on the message when a hosted file is also attached. Do not prepend flattened `text` when those body blocks are present. Do not probe target emoji catalogs for message body emoji; that probe is reactions-only.
- **Live vs stub is `workspaces.instance_id`.** Uninstall or Leave Connection pauses the row for the retention window (PostMeta stays). Uninstall with a pending peer claim converts to a stub (`heal_workspace_to_stub`). Reinstall, import of that Workspace, or reclaim on a live Slack event converts back (`heal_workspace_to_local`). That restore calls `heal_restored_sync_channels`: public Channels pause with a notice, the bot joins, then they resume; private Channels stay paused with a notice (twin Channel and admin DM when the bot cannot post). Inbound SyncChannel upsert from paused or left to active posts a resume notice on twin Channels that still have a bot token (Workspaces that stayed on the original instance). Reconnecting an External Connection unpauses that peer's stubs (`restore_peer_stubs`). Do not `purge_workspace` on Leave Connection.
- **In-process cache is per warm container (60s).** Writes that change fan-out or Home must invalidate the relevant participation/settings keys, the `home_tab_hash:` prefix, and `fed_ws_for_sync:` after federation pair/unpair/restore. Pause/Leave/uninstall must invalidate **every** Channel in the sync, not only this workspace's Channel — `publish_targets:{origin}` is keyed by the publisher.
- **Message-body `#channel` stays source.** Never remap a synced message's `#channel` mention to the target twin. Render `` `#name (Workspace)` `` (code ticks), including federation. Do not emit target `<#C>`, `slack://`, `app.slack.com/client`, or channel-only `archives/C` URLs. Home may still use native `<#C>` for **this** workspace's own channel. Rich_text `{type: channel}` becomes a `text` element with `style.code`.
- **Source message permalinks stay labeled source URLs.** Keep `…/archives/C…/p…`. Slack pastes those as `message_mention`; convert to `{type: link}`. Unlabeled permalinks get `message in #channel (Workspace)`; existing link text stays. Do not emit `slack://` or `app.slack.com/client`. Target `chat.postMessage` / `chat.update` set `unfurl_links=false`. Never leave mrkdwn `<url|label>` inside a rich_text `text` node; emit a real `link` element.
- **Scope lockstep.** `slack_manifest_scopes.py` + `slack-manifest.json` / `_test` / `_prod` + SAM/Terraform defaults + env examples. User scopes that do not match the Slack app fail install with `invalid_scope`.
- **`get_oauth_flow()` is `None` in local single-workspace mode.** Hide Authorize if there is no install URL.
- **`PRIMARY_WORKSPACE` gates instance Settings fields, backup/restore, DB reset, and External Connections** — not the Settings button on other workspaces (Slack admins there edit workspace fields only). Backup/reset also need the matching team; reset also needs `ENABLE_DB_RESET`. Do not add that workspace to a group or make it a group owner for being primary.
- **Group succession is purge-only.** Uninstall keeps the group; Home shows remaining members with no owner until retention ends. After the retention window, promote the earliest-joined remaining local member or disband. Home does not promote on read. Leave requires another active owner; a sole member sees Disband Group, not Leave Group. `PRIMARY_WORKSPACE` may join or be invited; it is never auto-added or made owner for being primary.
- **Channels may participate in multiple syncs.** This enables fan-in. A Channel may be published in more than one group. Reject subscribing one workspace to the same published source twice; do not reject a target merely because it participates in another sync.
- **Files live in `/tmp`.** That is the scratch directory the app can write. Clean up on failure.
- **Encrypt bot tokens on write, decrypt on read.** Encryption is off when the key is missing, shorter than 16 characters, or a placeholder (`123`, `changeme`, `secret`, `password`). Federation webhooks are HTTPS-only in production; HTTP only when `LOCAL_DEVELOPMENT`.
- **Group role `admin` is reserved and never written.** Do not start using it; no permission attaches yet.
- **Lambda migrations**: AWS deploy invokes migrations **once post-deploy**, then `{"action":"ready"}` (federation pulse and Home republish). Avoid relying on slow migration work during Slack request handling / cold start ack timeouts. The function timeout is 120s for that invoke; do not drop it back to 30s. Inbound federation returns **503** when identity/DB is not ready so origin retries 5xx.
- **SQLite vs MySQL/Postgres** — local SQLite behaves differently for locking and types; don’t assume parity without checking migration scripts. See **Pytest warnings** above for `001_baseline` FKs and datetime adapters.
- **`ENABLE_DB_RESET`** — boolean (`true`/`1`/`yes`), gated by `PRIMARY_WORKSPACE`; don't treat as team-id string anymore.
- **`DATABASE_BACKEND`** + **`DATABASE_*`** — use `DATABASE_BACKEND` (`mysql` / `postgresql` / `sqlite`) and `DATABASE_HOST` / `DATABASE_USER` / `DATABASE_PASSWORD` / `DATABASE_SCHEMA` per [docs/INFRA_CONTRACT.md](docs/INFRA_CONTRACT.md).
- **Fork vs upstream** — `origin` may be your fork; open PRs against the repo you were asked to target (usually **F3Nation-Community/slack-syncbot** `main`). `release.yml` and Dependabot auto-merge run only on that canonical repository. Canonical GitHub bot identity is App **`f3n-community-automation`** (see [docs/DEVELOPMENT.md](docs/DEVELOPMENT.md)); forks do not install it.
- **User scopes on Home** — do not paste Slack API names (`groups:write`) onto **Authorize SyncBot**. Add the scope to `USER_SCOPES` *and* a row (or an existing fold) in `USER_PERMISSION_GROUPS` in [`syncbot/slack_manifest_scopes.py`](syncbot/slack_manifest_scopes.py). The comment on that constant is the labeling recipe: Slack scopes docs → 2–4 ordinary words, fold read/write twins, keep `groups:write` separate. Tests in `tests/test_slack_manifest_scopes.py` require every user scope in exactly one group.
- **OAuth starts at `/slack/install`.** Never link at `slack.com/oauth/v2/authorize`. Bolt requires the state cookie that only this instance's install path sets; otherwise Allow fails with `invalid_browser`. After a successful callback, refresh that user's Home (`refresh_home_after_oauth_install`) so Authorize disappears without a manual Refresh. On Lambda Function URL payload 2.0, put that cookie in the `cookies` array (not `Set-Cookie` headers) and 404 stray GETs such as `/favicon.ico` so they do not overwrite it. After a user-token revoke, `InstallationStore.delete_installation` for that `user_id` (do not leave a tokenless row). After uninstall, `delete_all` plus workspace pause. Do not enable Bolt's `enable_token_revocation_listeners()`: Slack may send `tokens.bot` on a personal revoke, and that builtin would drop the workspace bot token. Uninstall only if `auth.test` on the stored bot token fails, or on `app_uninstalled`.
- **Public origin is request Host, not `SYNCBOT_PUBLIC_URL`.** Use `get_public_base_url` / `capture_public_base` (Authorize and federation). Leftover `SYNCBOT_PUBLIC_URL`, `SYNCBOT_INSTANCE_ID`, and `FILE_CHUNK_MB` are ignored and warned. The federation instance id is a SHA-256 fingerprint of the Ed25519 public key. Inbound file-part and JSON size are this hop's injected `FEDERATION_HTTP_MAX_MB` in [docs/INFRA_CONTRACT.md](docs/INFRA_CONTRACT.md) (`file_chunk_mb` / `json_chunk_mb`; `0` means this hop did not inject a cap). Slack files stay 1 GB. The sender splits to the peer's advertised cap; `0` or omitted is one part, never a guessed MiB default. A 413 retries only when the peer advertises a smaller positive cap. Do not detect `K_SERVICE` or `AWS_LAMBDA_FUNCTION_NAME` for this. Tests assert behavior given a cap. Do not slice mentions or `files[:20]`. Remap every `<@U…>`. Page `/users` on the existing path. Do not add leftover names back as required env vars.
- **Federation auth order.** Ed25519 is `sign(timestamp + ":" + raw_body)`. Once the `SyncBot-Federation` User-Agent is present: missing or malformed headers are **400**, well-formed but untrusted is **401**. Do not `json.loads`, DNS, apply, or upsert until headers and verify pass. Pair looks up the pairing code before `validate_webhook_url`. Fingerprint-only Instance lookup (no leftover UUID key scan). Slack `POST /slack/events` on the HTTP listener is **413** over this hop's injected cap when set.
